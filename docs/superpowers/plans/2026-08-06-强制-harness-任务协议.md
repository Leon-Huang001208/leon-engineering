# 强制 Harness 任务协议实施计划

> **供代理执行：**必须使用 `subagent-driven-development`（推荐）或 `executing-plans` 逐任务执行；所有步骤使用复选框追踪。

**目标：**让跨宿主项目交付自动进入 Harness，并由可运行的交付检查拒绝无证据的完成状态。

**架构：**在现有项目账本旁增加隐私受限的事件流和 `harness-session` 自动入口；Claude 插件与 Codex 用户级工具 Hook 都调用它。两个宿主最终都由同一只读 `harness-enforce` 命令及项目 CI 硬门验证。

**技术栈：**Node.js 内置模块、Node 测试运行器、JSON Lines、Claude Code Hook、GitHub Actions。

### Task 1：定义事件流与自动会话（TDD）

- [ ] 在 `tests/harness-project.test.mjs` 新增事件仅允许白名单字段、拒绝任意文本/路径/命令字段的失败断言。
- [ ] 运行 `node --test tests/harness-project.test.mjs`，确认新增断言失败。
- [ ] 在 `scripts/harness-project.mjs` 实现安全追加 `events.jsonl`、启动/验证完成事件和现有目录的符号链接防护。
- [ ] 新建 `tests/harness-session.test.mjs`，覆盖首次自动创建、已存在 Harness 追加任务、同一会话恢复和不泄露目标文本到事件流。
- [ ] 新建 `scripts/harness-session.mjs`，实现 `--start`、受控任务 ID、会话上下文和 JSON 输出。
- [ ] 运行两套 Harness 单测，确认通过后提交该独立功能。

### Task 2：实现可执行交付硬门（TDD）

- [ ] 新建 `tests/harness-enforce.test.mjs`，分别构造缺少会话、未完成、验证失败、通过结果四种夹具。

- [ ] 新建 `scripts/harness-enforce.mjs`；只读检查任务、结果、事件，不执行项目命令。
- [ ] 为 `--help`、符号链接拒绝和 CLI 非零退出码加入测试。
- [ ] 运行 `node --test tests/harness-enforce.test.mjs tests/harness-project.test.mjs`，确认全绿后提交。

### Task 3：接入 Claude Hook 与受管运行时（TDD）

### Task 5：安装并做 AlphaFoundry 真实试运行

- [ ] 用临时主目录测试 Codex/Claude 安装器与运行时安装器，确认不覆盖用户内容。

- [ ] 若要将硬门接入 AlphaFoundry 的 CI，先列出将修改的工作流与命令，取得针对项目 CI 的确认；未确认前不修改 CI。
- [ ] 将已执行命令、输出和未验证边界记录到框架的 `docs/pilot-results.md`，不把预览或未运行的 CI 说成通过。

## 计划自检

- 覆盖设计中的自动入口、事件隐私、Claude Hook、Codex 真实边界、硬门、运行时、文档和 AlphaFoundry 试运行。
- 无待定占位项；每项都指定了文件、命令或可观察的验收证据。
- 事件字段、任务 ID 与 `completed/passed` 的命名在所有任务中一致。
