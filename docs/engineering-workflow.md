# 统一工程工作流

日常直接说明目标与边界，由 `leon-engineering:agent-routing` 确认项目、风险和工作类型。它是原有 Skill 的职责扩展，不增加一个同名主入口；规范 core 的九个 Skill 身份与插件 ID 保持兼容。

| 请求 | 路径 | 规范正文 |
| --- | --- | --- |
| 增加或调整行为 | 主入口 → 功能开发 | `agent-routing/references/feature-development.md` |
| 修复已有缺陷 | 主入口 → 缺陷修复 | `agent-routing/references/defect-repair.md` |
| 只读审查或证据核验 | 主入口 → 评审 | `agent-routing/references/review.md` |
| 显式调用 feature-loop / bugfix-evidence / review-ship | 兼容入口 → 同一主入口与对应正文 | 无第二份流程 |

先选择风险，再按实质工作需要读取一条匹配的子流程；不预读所有子流程。普通聊天和单个已知只读命令不进入工程子流程；简单只读解释也不因主入口存在而增加通用探索。项目规则仍决定必需前置检查。只有真正设计测试或作范围内的架构判断时，才读取原路径的 engineering-methods 参考；只有确有委派收益或隔离需要时才进入角色模板。小任务不新增流程性提问、计划或代理。

## 验证与授权

四档风险名称保持 read-only、local-only、isolated、full-delivery。小改必须可证明局部、可逆、无冲突且不影响公开契约、schema、依赖、CI、数据库、安全、桌面或跨平台；否则按项目策略升级。只读任务不建 worktree、不修改项目内容。普通小改只做项目需要的验证，不建立或记录 Harness。

风险升级不自动选择账本或发布控制器。交付遵循项目已有流程；只有项目规则或当前任务显式选择受管控制器时才读取 iteration-delivery 的完整协议，并使用其中 delivery-required / require-delivery 的门禁。当前任务授权决定能否发布，Skill 不提供长期推送或合并授权。

项目 `.agents/verification-policy.json` 仍是完整变更集到验收的唯一机器路由。最近的回归测试不能替代固定合同、适用 CI、原生平台证据或项目已明确选择的验收门。缺失、未运行或受阻保持真实状态；高风险升级不扩大授权，no-push、只读和仅评审边界持续有效。

评审默认只读，报告严重性、证据与最小修复建议；用户已授权修复时才进入缺陷修复分支。评审通过不等于可以发布。任务交接统一列出实际变更、验证结果、未验证项和阻塞，不把候选命令写成执行证据。

## 兼容与分发

三个旧 SKILL.md 保留原 name、目录和可调用路径，描述收窄为显式兼容调用，并链接到主入口及对应子流程。旧 engineering-methods 路径与来源许可保留。插件目录安装和平铺 adapter 安装都必须能解析这些链接；合同测试同时验证两种布局。

九个可发现 core 身份与旧路径保持兼容，三个包装入口仍存在。本轮不再注册全局或插件自动 Hook；全局安装只写短策略和指南，运行时由明确选择它的项目或任务单独安装和调用。不能用已删除的自动边界继续宣传强制账本已生效。

全局策略只保留项目、授权、证据和入口提示。工程师、测试、安全等岗位方法由角色说明或匹配 Skill 按需提供；项目命令留在目标项目。角色 AGENTS 的能力列表不是已安装工具或已获得权限的证据，执行链必须实际提供这些能力。直接使用 Codex 时仍可从同一规范 Skill 进入，不依赖 Paperclip 调度。

更新按受管源 → 合同 → 宿主分发 → 实际加载核验进行，不手改安装缓存。已有聊天可能缓存目录；源码更新、CLI 新会话与桌面进程的实际加载状态分别报告。

同名外部软链接可能让宿主先读取旧入口，再读取规范插件。先记录实际访问与来源；只有用户明确授权后才把链接本身移出默认扫描目录，备份链接并核对目标整树未变，不删除或覆盖外部目标。保留既有 restored/hash 检查，不能为健康状态变绿而忽略冲突。
