# 主动框架学习

此规则让跨项目可复用的执行经验成为可验证的全局改进，而不是遗失在单次对话里。

## 触发条件

主动创建候选的信号包括：已证实的执行错误、用户纠正、重复返工、错误的能力/代理路由，或有证据证明能提升多类任务的速度、质量或安全性。只处理可跨项目复用的模式；不记录项目特定的事实、用户内容、秘密、路径或一次性偏好。

## 自动推广

候选同时满足“有实际证据”和“低风险”时自动推广：先添加或修改回归测试，再更新受管源与相关工作流文档，安装到 Codex/Claude 全局副本并校验，最后提交并记录证据。低风险指不改变权限、秘密处理、依赖、远程操作、发布、迁移、CI/CD、系统配置或破坏性边界。

## 升级确认

任何会改变上述高风险边界、需要外部安装/升级，或影响面无法从证据确定的候选，都先向用户说明影响并取得明确确认；不得以“学习”为理由绕过现有安全规则。

## 记录格式

每项已推广的经验在 `docs/pilot-results.md` 记录：触发信号、可复用结论、变更的受管源与测试、实际验证、安装版本、未验证项和风险。记录只保留必要的非敏感事实。
