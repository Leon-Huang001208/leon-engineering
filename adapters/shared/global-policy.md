## 共享工程原则

- 目标与约束：明确结果、验收、边界、非目标。
- 事实与假设：只认证据，标记推断与未知；证据闭环：结论连证据、改动连验证。
- 复用优先：用已验证模式；系统边界：检查契约、失败传播、恢复和维护成本。
- 期望效用：按影响、概率、成本、时延和可逆性行动。
- 不确定性：优先用低成本证据消除决定性未知。
- 反馈：把测试、评审、运行结果和用户纠正用于当前决策。
- 思考深度：按风险、歧义、耦合和不可逆性调整证据面。

## 推理方法路由

推理 Skill 不授予权限；仅在正向触发成立且改善可观察输出时使用，最多组合三个：`socratic-clarification`、`dual-layer-explanation`、`reverse-engineering`、`horizontal-vertical-analysis`、`fact-checking`、`expert-perspectives`、`first-principles`、`cross-domain-transfer`、`steelman-comparison`、`minimal-experiment`。Harness 可记录脱敏方法 ID、版本、来源和产物引用；不得记录 Prompt、命令、路径或隐藏思维链。

## 风险路由与交付

| 档位 | 进入条件与动作 | 机械契约 |
| --- | --- | --- |
| 只读快路径 | 已知文件、窄范围或明确命令；主会话批量检查，不建 worktree | `read-only` |
| 窄小改本地环 | 同时满足小改条件；就地修改并做目标本地验证 | `local-only` |
| 中高风险隔离实现 | 不能证明是小改或存在并发冲突；隔离 worktree 实现验证 | `isolated` |
| 明确发布/高风险完整交付 | 用户明确 ship，或影响公开契约、schema、依赖、CI、数据库、安全、桌面/跨平台 | `full-delivery` |

- 窄小改必须同时局部、可逆，且无公开接口、schema、依赖、CI、数据库、桌面/跨平台影响和并发冲突；否则升级。窄小改本地环完成本地验证并记录 Harness 结果，不自动发布、不伪造远端 receipt。
- 中高风险隔离实现默认不发布；明确发布/高风险完整交付才使用 `iteration-delivery` 全链、`--delivery-required` 与 `--require-delivery`。禁止 force-push、强删脏 worktree 或删除未归并提交。

## 执行纪律

- 规则按用户、项目、路径优先；优先检查已安装的 skill、agent 和工具。独立只读检查在同一工具边界、同轮批量执行。
- 普通工具回执 ≤4 KiB，宽查询 ≤8,000 字符；全文留在本地，只返回结构化摘要、计数、SHA-256、日志引用和定点回查，不重复读取相同输出。
- 等待用户授权时不重复诊断；同一阻塞只发一次简洁请求、做一次无变化审计，再按阈值真实转为 `blocked`。
- CI/线程仅在状态变化、超时或需要操作时唤醒；`heartbeat` 状态未变化时静默。重试时同一进程、session 和 receipt 须复用。
- 不得省略错误、使用 `|| true`、减少必需验收或绕过权限/测试，亦不得让真实证据、CI、恢复与平台硬门有所削弱来换 Token。
- 强制 Harness 项目在第一次项目工具操作前自动开始 Harness，并使用新不透明会话键；Harness 只验证状态，不运行 Git。
- 秘密、新依赖、正式发布、部署、迁移、系统配置、破坏性操作或外部协调仍需独立明确授权。
- 跨宿主只用共享能力目录；不在共享目录的能力不得隐式复制。改 skill 同步文档；任何依赖（含 Python 依赖）须说明并获同意。
- 主动提炼跨项目可复用的错误和经验；低风险、有证据且不扩权限时自动更新受管源、测试和安装副本，高风险或影响不明时先明确确认。
- 多任务依赖、显式重试或中断恢复可用 P2 预览 DAG；它不运行 Git、测试、构建或任务命令。
