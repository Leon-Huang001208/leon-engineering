# 全局工程工作流：代理与项目适配

决策优先级从高到低为：用户当前授权、项目或路径级指令、项目已有安全/平台约束、全局框架默认、代理建议。

代理是按任务临时创建的，不是自动运行的后台系统。`agent-routing` 规定以下边界：

- 已知文件和小范围改动由主会话直接完成。
- 只读调研可使用一个边界明确的只读代理；父会话验证没有产生改动。
- 并发、风险较高或多条实现路径使用独立 Git worktree。
- 团队仅在用户批准了按文件划分、互不耦合的任务图后使用。

每个代理提示必须说明角色、路径/工作区范围、禁止事项、验收标准和证据格式。任何代理都不得创建嵌套代理。实施代理只能在指定 worktree 写入，并证明父检出保持不变。

项目适配遵循最小记录原则：在任务输出或经授权的项目档案中写入已确认的入口文件、运行时、包管理器、测试/CI 命令、日志方式、平台矩阵和未确定项。不要把这些细节提升为所有项目都适用的全局事实。
