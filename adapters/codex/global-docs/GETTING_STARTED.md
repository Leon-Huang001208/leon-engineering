# 全局工程工作流：快速开始

这套工作流适用于每一个由 Codex 处理的项目类型，包括前端、后端、桌面端、数据工程和文档；它不是某一个仓库的模板。

每次任务按以下顺序工作：

1. 识别用户目标、目标项目和相关项目规则；不把“所有项目”理解成可以批量改写本机仓库。
2. 快速检查已安装能力：匹配的 skill、agent 或工具优先使用；没有匹配项就继续，不因寻找外部能力阻塞任务。
3. 按四档路由选择最小流程：只读快路径、窄小改本地环、中高风险隔离实现、明确发布/高风险完整交付。
4. 只有项目陌生且确实需要证据时，才使用 `project-adapter` 生成只读档案；它列出证据与候选命令，但不运行命令，也不代表验证通过。
5. 按任务风险选择最小验证和最少的代理；只在探索、并行或隔离有明确收益时使用 `agent-routing`。
6. 必要时用 `project-bootstrap` 只记录已验证的项目事实；仅在用户明确授权时写入项目档案。
7. 对已启用强制 Harness 的目标项目，在第一次项目工具操作前自动开始新任务；任务延续时恢复其上下文。用户不需要手工创建账本。
8. 窄小改只有同时局部、可逆、无公开接口/schema/依赖/CI/数据库/桌面影响且无并发冲突才走本地环；记录 Harness 结果，但不自动发布或伪造远端 receipt。不能证明时升级为隔离实现。
9. 只有用户明确 ship，或任务影响公开契约、schema、依赖、CI、数据库、安全、桌面/跨平台时，才使用完整 `iteration-delivery`、`--delivery-required` 和 `--require-delivery`；报告真实结果与剩余风险。
10. 执行中发现跨项目可复用的错误或经验时，按[主动框架学习](../../docs/framework-learning.md)判断：低风险且有证据的修正自动落盘、测试、安装和记录；高风险或影响面不明时先确认。

只有用户明确授权时，才通过 `project-adapter --write-profile` 把 `.ai/project-profile.json` 持久化写入某个项目；默认只读且拒绝覆盖。项目特定细节不应被写进全局策略。
