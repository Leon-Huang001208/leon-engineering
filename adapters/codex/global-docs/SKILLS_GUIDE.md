# 按需技能分工

核心插件保持九个稳定 Skill 身份，不附带自动 Hook，不默认安装运行时。三个旧入口只转发，不维护第二份流程。

| Skill | 触发范围 |
| --- | --- |
| `agent-routing` | 实质工程任务的项目、风险与单一子流程选择；跳过聊天和已知单条只读请求。 |
| `feature-loop` / `bugfix-evidence` / `review-ship` | 显式兼容入口，转发至功能、修复或默认只读评审正文。 |
| `project-adapter` | 陌生且用户选定项目的只读证据与候选命令。 |
| `project-bootstrap` | 建立获准的项目说明，不扫描或改写其他项目。 |
| `project-constraints` | 用户选定项目的架构、文档联动和平台静态约束。 |
| `project-harness` | 项目或任务显式选择跨会话账本、恢复与指标时。 |
| `iteration-delivery` | 项目或任务显式选择受管 Git 交付控制器时。 |

普通工作不创建或记录 Harness。高风险意味着更充分的项目验证和必要隔离，不自动选择账本、发布控制器或远端写入。项目已明确选择的验收与权限门继续执行。

工程师等岗位指令可引用所需 Skills；手动 Codex 也使用同一份规范方法。Skill 是操作说明，工具、插件、MCP 和权限必须由实际执行环境提供。

可选 `leon-engineering-workflows` 承载推理方法和专项能力，`leon-engineering-commands` 承载旧命令包装，均不自动安装。可用能力先查当前宿主；外部候选只有预计有收益时才审查来源、依赖、许可证和权限，并获准安装。

同名入口不得仅按名称删除。全局退役和项目复制继续使用既有 portfolio 的哈希预检、私有备份、sanitizer 与回滚。项目事实留在项目，跨宿主能力以共享目录及实际加载证据为准。
