## 全局工程工作流（leon-engineering 受管区块）

- 本区块是所有项目的默认工程基线；用户请求、项目级 `AGENTS.md`、路径级规则及仓库已有约定优先。
- 在选择执行路径前，优先检查已安装的 skill、agent 和工具是否直接匹配当前任务；命中则按其触发条件使用，未命中才以通用能力直做。该本地能力检查属于快路径，不创建计划、代理或 worktree；不能把未检查可用能力合理化为直接执行。
- 对已知文件、范围明确的只读或非实现工作，默认走快路径：主代理直接完成，不创建计划、不调用子代理、不创建 worktree，也不得为了流程而向用户提问。只有范围不明、探索明显阻塞主任务或并行工作有明确速度收益时才升级；主代理负责汇总与验证。
- 每项任务只识别和检查用户指定的目标项目。不得因为项目在本机、受信任列表或历史记录中出现，就批量扫描、修改、提交或推送其他项目。
- 对用户指定 Git 项目中的实现性改动，默认自动使用 `iteration-delivery` 完成闭环：从最新远端默认分支创建任务分支和隔离 worktree，提交并做分支验证，在临时集成 worktree 合并并重新验证，发布远端默认分支，等待 CI，再安全删除本地/远端任务分支和全部临时 worktree。默认分支从 `origin/HEAD` 识别；优先直推，保护规则拒绝时自动转 PR 并启用自动合并。该长期策略已授权，不得再次询问是否合并、推送或删除分支。
- 显式 `no-push`、仅本地、草稿、调研、评审或只读任务不自动发布。项目级规则、分支保护、平台验证、秘密、依赖、发布、迁移和其他独立授权边界仍优先。全程禁止 force-push、强删脏 worktree 或删除未进入默认分支的提交；CI 失败最多修复三轮，之后只在远端 tip 完全属于本任务且回滚验证通过时自动回滚，否则保留现场并报告阻塞。
- 对用户已启用强制 Harness 的目标项目，任何会形成项目交付、改动或调研结论的新任务都必须在第一次项目工具操作前自动开始 Harness；使用新的不透明任务键和 `harness-session.mjs --start --new-task`，不得要求用户手工建账。任务继续时恢复既有上下文；纯聊天和未指定项目的知识问答不创建项目记录。
- Codex 全局 `PreToolUse`/`PostToolUse` Hook 会在本地工具边界自动建立或恢复 Harness 上下文，并记录非敏感事件；初始化失败时只放行 `pwd`、配置/指令读取、`rg`/只读 `sed`、Git 只读命令和受管 runtime 自检等明确 `diagnostic_read`，`mutation` 与 `unknown` 继续 fail closed。诊断只输出阶段、错误码、runtime/manifest 路径和恢复建议。实现任务以 `--delivery-required` 建账，最终运行 `harness-enforce.mjs --project <项目目录> --task-id <任务 ID> --require-delivery`；硬门除真实验证证据外还实时核验 receipt、远端提交、CI、任务分支和 worktree。Harness 只验证状态，不直接运行 Git。
- 在改动前读取目标项目的指令、架构入口、运行方式、测试、日志和 CI 约定；仅记录已由文件或命令验证的事实。需要把项目档案写入仓库时，先取得明确授权。
- 依据耦合度和风险选择直接执行、只读调研、隔离 worktree 或用户明确同意的代理团队。代理不得递归委派；涉及秘密、依赖、远程变更、发布、迁移、CI、全局配置或破坏性操作时升级处理。
- 代码改动使用项目的日志和错误处理模式，并运行与风险相称的实际验证。交付必须区分已执行的证据与未验证的平台、环境或风险。
- 外部 skill、插件或 agent 必须经历“发现 → 来源/权限审查 → 用户明确安装 → 隔离验证 → 再评估是否推广”的流程。不得自动从网络安装、信任或升级它们。
- 跨宿主可用能力以 `docs/shared-capability-catalog.md` 为共享能力目录；只路由其中明确标记为共享的 skill 和职责代理。不在共享目录的 Claude 专用 skill、agent 或规则只能作为候选证据，不得隐式复制、安装或当成 Codex 默认能力。
- 修改任何共享 skill 时必须同步更新其文档；添加或更新任何依赖（包括 Python 依赖）前，必须说明用途、影响和目标文件并取得用户明确同意。
- 在执行中主动提炼跨项目可复用的错误和经验；不得等待用户再次指出。对有实际证据且不改变权限、秘密、依赖、远程、发布、迁移、CI/CD、系统配置或破坏性边界的低风险修正，自动更新受管源、测试和安装副本，并记录验证证据。上述高风险类别或影响面不明的修正必须先取得明确确认；项目特定事实不提升为全局规则。

详细入口、结构、命令、技能、代理和设置边界见 `docs/` 下的全局工作流文档。
