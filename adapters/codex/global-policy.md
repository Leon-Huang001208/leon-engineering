## 全局工程工作流（leon-engineering 受管区块）

- 本区块是所有项目的默认工程基线；用户请求、项目级 `AGENTS.md`、路径级规则及仓库已有约定优先。
- 在选择执行路径前，优先检查已安装的 skill、agent 和工具是否直接匹配当前任务；命中则按其触发条件使用，未命中才以通用能力直做。该本地能力检查属于快路径，不创建计划、代理或 worktree；不能把未检查可用能力合理化为直接执行。
- 对已知文件、范围明确的改动或已有明确命令的工作，默认走快路径：主代理直接完成，不创建计划、不调用子代理、不创建 worktree，也不得为了流程而向用户提问。只有范围不明、探索明显阻塞主任务、并行编辑有明确速度收益，或风险/耦合需要隔离时才升级；主代理负责汇总与验证。
- 每项任务只识别和检查用户指定的目标项目。不得因为项目在本机、受信任列表或历史记录中出现，就批量扫描、修改、提交或推送其他项目。
- 在改动前读取目标项目的指令、架构入口、运行方式、测试、日志和 CI 约定；仅记录已由文件或命令验证的事实。需要把项目档案写入仓库时，先取得明确授权。
- 依据耦合度和风险选择直接执行、只读调研、隔离 worktree 或用户明确同意的代理团队。代理不得递归委派；涉及秘密、依赖、远程变更、发布、迁移、CI、全局配置或破坏性操作时升级处理。
- 代码改动使用项目的日志和错误处理模式，并运行与风险相称的实际验证。交付必须区分已执行的证据与未验证的平台、环境或风险。
- 外部 skill、插件或 agent 必须经历“发现 → 来源/权限审查 → 用户明确安装 → 隔离验证 → 再评估是否推广”的流程。不得自动从网络安装、信任或升级它们。
- 跨宿主可用能力以 `docs/shared-capability-catalog.md` 为共享能力目录；只路由其中明确标记为共享的 skill 和职责代理。不在共享目录的 Claude 专用 skill、agent 或规则只能作为候选证据，不得隐式复制、安装或当成 Codex 默认能力。
- 修改任何共享 skill 时必须同步更新其文档；添加或更新任何依赖（包括 Python 依赖）前，必须说明用途、影响和目标文件并取得用户明确同意。
- 在执行中主动提炼跨项目可复用的错误和经验；不得等待用户再次指出。对有实际证据且不改变权限、秘密、依赖、远程、发布、迁移、CI/CD、系统配置或破坏性边界的低风险修正，自动更新受管源、测试和安装副本，并记录验证证据。上述高风险类别或影响面不明的修正必须先取得明确确认；项目特定事实不提升为全局规则。

详细入口、结构、命令、技能、代理和设置边界见 `docs/` 下的全局工作流文档。
