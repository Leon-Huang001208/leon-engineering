本受管区块优先于旧目录或旧代理目录中“默认先规划、先委派或全量验证”的建议；项目规则和明确风险升级要求仍优先。

在选择执行路径前，优先检查已安装的 skill、agent 和工具是否直接匹配当前任务；命中则按其触发条件使用，未命中才以通用能力直做。该本地能力检查属于快路径，不创建计划、子代理或 worktree；不能把未检查可用能力合理化为直接执行。

范围明确、可逆且不形成 Git 实现交付的任务，默认走快路径：先只读与当前任务直接相关的文件，再直接完成，并只运行能够证明本次工作的最小相关验证。

快路径中不得为了流程创建计划、子代理或 worktree，不运行无关检查，也不得进行流程性提问。主代理负责汇总变更、验证证据和未验证项。

对用户指定 Git 项目中的实现性改动，默认自动使用 `iteration-delivery` 完成闭环：从最新远端默认分支创建任务分支和隔离 worktree，提交并做分支验证，在临时集成 worktree 合并并重新验证，发布远端默认分支，等待 CI，再安全删除本地/远端任务分支和全部临时 worktree。默认分支从 `origin/HEAD` 识别；优先直推，保护规则拒绝时自动转 PR 并启用自动合并。该长期策略已授权，不得再次询问是否合并、推送或删除分支。

显式 `no-push`、仅本地、草稿、调研、评审或只读任务不自动发布。项目级规则、分支保护、平台验证、秘密、依赖、发布、迁移和其他独立授权边界仍优先。全程禁止 force-push、强删脏 worktree 或删除未进入默认分支的提交；CI 失败最多修复三轮，之后只在远端 tip 完全属于本任务且回滚验证通过时自动回滚，否则保留现场并报告阻塞。

范围不明、调研受阻或并行工作有明确速度收益时，才升级代理或调研方式。实现闭环以外涉及秘密、新依赖、正式发布、部署、迁移、系统配置、破坏性操作或外部协调时，仍必须先询问并获得明确授权。

对用户已启用强制 Harness 的目标项目，任何会形成项目交付、改动或调研结论的新任务都必须在第一次项目工具操作前自动开始 Harness；使用新的不透明任务键和 `harness-session.mjs --start --new-task`，不得要求用户手工建账。Claude 插件的写入型工具 Hook 会建立或恢复同一会话的 Harness 上下文；初始化失败时拒绝项目写入。任务继续时恢复既有上下文；纯聊天和未指定项目的知识问答不创建项目记录。

实现任务以 `--delivery-required` 建账，最终运行 `harness-enforce.mjs --project <项目目录> --task-id <任务 ID> --require-delivery`；硬门除真实验证证据外还实时核验 receipt、远端提交、CI、任务分支和 worktree。Harness 只验证状态，不直接运行 Git。

在执行中主动提炼跨项目可复用的错误和经验；不得等待用户再次指出。对有实际证据且不改变权限、秘密、依赖、远程、发布、迁移、CI/CD、系统配置或破坏性边界的低风险修正，自动更新受管源、测试和安装副本，并记录验证证据。上述高风险类别或影响面不明的修正必须先取得明确确认；项目特定事实不提升为全局规则。

跨宿主可用能力以 `docs/shared-capability-catalog.md` 为共享能力目录；只路由其中明确标记为共享的 skill 和职责代理。不在共享目录的 Claude 专用 skill、agent 或规则只能作为候选证据，不得隐式复制、安装或当成 Codex 默认能力。

修改任何共享 skill 时必须同步更新其文档；添加或更新任何依赖（包括 Python 依赖）前，必须说明用途、影响和目标文件并取得用户明确同意。

对已初始化 Harness 的多任务依赖、显式重试或中断恢复，先用 P2 控制平面预览任务 DAG。它只保存项目内任务状态和已存在 worktree 的定位信息；不得自动创建、切换或删除 worktree，不得自动重试，也不得运行 Git、测试、构建或任务命令。
